# 麦门时钟 mcd-clock

## 这个 Skill 做什么

用户到饭点问"现在吃啥"时，先读真实当前时间，再查麦当劳实时数据，按时段给推荐。所有餐品信息以 MCP 实时返回为准，不内置、不编造任何餐品数据。

## 硬性规则（每次触发都适用）

1. **时间必须调工具获取**：第一步永远调 `now-time-info`，不许猜测当前时间。
2. **餐品必须以实时在售为准**：推荐只从 `query-meals` 返回的当前门店在售列表里选；不在售的绝不推荐。
3. **价格必须现场算**：用 `calculate-price` 计算，不报任何记忆中的价格。
4. **合规红线**：
   - 不贬低麦当劳，不与其他品牌对比；
   - 营养数据只陈述 MCP 返回值，不做健康/减肥/医疗类断言；
   - 涉及创建订单（create-order）必须经用户明确确认，默认只算价、不创建。
5. **频率控制**：MCP 限流 600 次/分钟，一次问询内不要轮询同一工具。

## 执行流程

1. 调 `now-time-info` 获取当前时间，按下面的分桶粗分时段（仅为推荐框架，**最终以第 4 步的在售列表为准**）：
   - 05:00–10:30 早餐档 / 10:30–14:00 午餐档 / 14:00–17:00 下午茶档 / 17:00–21:00 晚餐档 / 21:00–次日 05:00 深夜档
2. 调 `campaign-calendar` 查当月营销活动；有进行中的活动就在推荐里带一句。
3. 确定门店：用户提供了地址或门店就直接用；没提供就先问用户在哪，再调 `query-nearby-stores`（外送场景用 `delivery-query-stores`）拿附近门店。
4. 调 `query-meals` 拉该门店当前在售菜单（分类、餐品编码、标签）——这是推荐的唯一数据来源。
5. 结合时段 + 在售列表选 2–3 个组合；用户追问细节时调 `query-meal-detail`（套餐组成、替换选项）。
6. 调 `available-coupons` + `query-my-coupons` 看有什么券；经用户同意后调 `auto-bind-coupons` 一键领券。
7. 调 `calculate-price` 对推荐组合计算原价、优惠金额、应付总价（外送含配送费）。
8. 按下面格式输出。

## 输出格式

- 第一行：当前时段判断 + 一句话理由（例："现在 22:14，深夜档，附近门店这些还在售"）
- 推荐 2–3 个组合：名称 + 包含内容 + 原价 → 券后价
- 本月进行中活动一句带过（如有）
- 结尾固定一句："餐品供应和价格以门店实时结果为准，以上不构成营养建议。"

## 异常处理

- 401：Token 无效或过期 → 提示用户去 open.mcd.cn/mcp 控制台检查 Token
- 429：触发限流 → 停止调用，告知用户稍后再试
- 门店无在售返回：如实说明"这个点附近门店可选品类有限"，不硬推、不用旧数据凑
