# 麦门时钟 mcd-clock

## 这个 Skill 做什么

用户到饭点问"现在吃啥"时，先读真实当前时间，再查麦当劳实时数据，按时段给推荐。所有餐品信息以 MCP 实时返回为准，不内置、不编造任何餐品数据。

## 硬性规则（每次触发都适用）

1. **时间必须调工具获取**：第一步永远调 `now-time-info`，不许猜测当前时间。
2. **餐品必须以实时在售为准**：推荐只从 `query-meals` 返回的当前门店在售列表里选；不在售的绝不推荐。
3. **价格必须现场算**：用 `calculate-price` 计算，不报任何记忆中的价格。
4. **合规红线**：
   - 不贬低麦当劳，不与其他品牌对比；
   - 营养数据只陈述 MCP 返回值，不做健康/减肥/医疗类断言；
   - 涉及创建订单（create-order）必须经用户明确确认，默认只算价、不创建。
5. **频率控制**：MCP 限流 600 次/分钟，一次问询内不要轮询同一工具。
6. **响应格式认知（2026-10-24 实测确认）**：
   - 大多数工具返回标准 JSON（外层 success/code/message/data）；
   - `campaign-calendar`、`available-coupons`、`query-my-coupons`、`auto-bind-coupons` 直接返回 **Markdown 文本**，按原文读取即可，不要尝试 JSON 解析；
   - `list-nutrition-foods` 返回 **TOON 紧凑格式**（表头一行+数据行），按表格理解；
   - 部分工具的文本内容带 Markdown 说明前缀/尾巴，真实数据是其中嵌入的 JSON——用"找 `{"success"` 起点的完整 JSON 对象"的方式提取。

## 执行流程

1. 调 `now-time-info`（无参数）获取当前时间，按下面分桶粗分时段（**仅为推荐框架，最终以第 4 步在售列表和门店返回的官方时段名为准**）：
   - 05:00–10:30 早餐档 / 10:30–14:00 午餐档 / 14:00–17:00 下午茶档 / 17:00–21:00 晚餐档 / 21:00–次日 05:00 深夜档
   - 实测参考：门店预约时段接口会返回官方时段名（如 早餐 07:14-10:15、午餐 10:44-14:15、下午茶 14:44-16:45、夜市 17:14-21:45、宵夜 22:14-22:46），各店可能有差异，以返回为准。
2. 调 `campaign-calendar`（无参数，默认当月）查营销活动；有进行中的活动就在推荐里带一句。返回是 Markdown，直接读。
3. 确定门店（默认走**到店自取**链路，最简单）：
   - 用户提供了城市+位置就直接用；没提供就先问一句"你在哪个城市、大概哪个位置"；
   - 调 `query-nearby-stores`：`{"beType": 1, "searchType": 2, "city": "<城市>", "keyword": "<位置关键词>"}`（beType=1 到店自取；searchType=2 按位置搜索，此时 city/keyword 必填）；
   - 从返回列表里选一家（优先营业中 businessStatus=true、距离近的），记下 **storeCode**。到店自取场景**不传 beCode**（只有得来速 beType=5、外送 beType=2、团餐 beType=6 才需要 beCode）。
4. 调 `query-meals`：`{"storeCode": "<storeCode>", "orderType": 1, "beType": 1}` 拉该门店当前在售菜单。返回含 categories（分类+餐品 code）和 meals（餐品详情 Map，含 currentPrice 现价）。
5. 结合时段 + 在售列表选 2–3 个组合。可选增强：
   - 用户关心热量时，调 `list-nutrition-foods`（无参数，TOON 格式）拿营养数据；菜单里的「500 大卡套餐」分类可优先用于热量敏感场景；
   - 用户追问套餐组成/替换选项时，调 `query-meal-detail`：`{"storeCode": ..., "orderType": 1, "beType": 1, "code": "<餐品code>"}`。
6. 优惠券两步走：
   - 调 `query-store-coupons`：`{"storeCode": ..., "orderType": 1, "beType": 1}` 看当前门店**可用**的券；
   - 调 `available-coupons`（无参数，Markdown 返回）看麦麦省**可领**的券；经用户同意后调 `auto-bind-coupons`（无参数）一键领取。
7. 调 `calculate-price`：`{"storeCode": ..., "orderType": 1, "beType": 1, "items": [{"productCode": "<code>", "quantity": 1}]}` 对推荐组合算价。注意：**返回金额单位是"分"，展示时除以 100 换成元**。
8. 按下面格式输出。

## 输出格式

- 第一行：当前时段判断 + 一句话理由（例："现在 22:14，深夜档，附近善缘街店这些还在售"）
- 推荐 2–3 个组合：名称 + 包含内容 + 原价 → 券后价
- 本月进行中活动一句带过（如有）
- 结尾固定一句："餐品供应和价格以门店实时结果为准，以上不构成营养建议。"

## 异常处理

- 401：Token 无效或过期 → 提示用户去 open.mcd.cn/mcp 控制台检查 Token
- 429：触发限流 → 停止调用，告知用户稍后再试
- 门店无在售返回 / 附近无门店：如实说明"这个点附近门店可选品类有限"，不硬推、不用旧数据凑
- 用户不肯提供位置：引导用户给出城市+地标，或改用外送链路（需先查/建配送地址，流程更长，先确认用户需要）
